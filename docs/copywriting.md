# 界面文案规范

纸鸢界面上的每一段文字都按本规范写。术语以第 5 节的术语表为准；机械规则由自动检查兜底（第 6 节）。
定稿：R-274（D-1162）。改规范时同步改术语表、`docs/copywriting-rules.json` 和第 6 节。

---

## 0. 一句话

**简洁、统一、平实的书面中文。** 不口语，也不打官腔：说清「是什么状态、发生了什么、能做什么」，不拟人、不聊天、不讲内部机制；同一个概念全站只有一个叫法。

---

## 1. 适用范围

### 1.1 归本规范管

| 类别 | 位置 |
|---|---|
| 网页界面文案 | `web/src/i18n/zh.ts`、`web/src/i18n/roles.ts`：按钮、菜单、标题、标签、状态、提示、空状态、确认框、toast、悬停说明 |
| 组件里零散的中文 | `web/src/lib/push.ts` 等；`command.tsx` 的搜索关键词例外（见 3.11） |
| 失败提示 | `web/src/lib/fail.ts`（句式见 3.8） |
| 后端生成、显示在网页上的文字 | `internal/hub`、`internal/store` 等：HTTP 错误说明（前端原样显示）、时间线条目、推送标题与正文、离开报告、送达 / 在线状态标签 |

判断不清时问一句：**这段字会不会出现在网页或推送上？** 会，就归本规范。

### 1.2 不归本规范管，但术语必须一致

| 类别 | 写法 |
|---|---|
| 身份提示词 `internal/roles/*.md`、MCP 工具说明、ks 命令行帮助 | 读者是模型，写法自定；**术语必须与第 5 节一致**（界面说「指派」，提示词也说「指派」） |
| Agent 写给用户的内容（证据、决策、阶段小结、留言） | 按 `internal/writing`（R-110、R-193）：短句、先结论、字数上限 |
| 用户自己写的内容（需求标题、留言、附言） | 原样显示 |
| 代码注释、日志 | 不管 |

### 1.3 用户和 Agent 都会读的文字

纸鸢提醒、订阅提醒、团队消息正文同时送给会话、又在「通讯」页显示。正文以会话为读者，可以写工具名和指令，但：

- 网页上显示的**标签、标题、类别、状态**按本规范写。
- 正文**第一句**是一句不含工具名的事实（「R-12 已提交验收」），工具指引放在后面，网页可以只取第一句做摘要。
- 受协议约束的格式不动（例如答复以「批准」开头，后端靠它判断，见 `zh.ts` 的 `decision.approve`）。

## 2. 语体与语气

### 2.1 基本要求

1. **书面、简洁、中性。** 用陈述句；不用感叹号、不用「您」、不写客套话（「请稍候」「感谢」「哦」）。
2. **不口语。** 「已完成」不写成「做完了」，「无进展」不写成「没动静」。
3. **也不打官腔。** 少用「该」「请」「代为」「进行」「予以」「将」：能写名字就写名字，能省主语就省，「会」比「将」平实。
4. **不拟人。** 会话、进程、纸鸢都不是人：不写「它挂着」「它管不到」「醒来」「干活」。
5. **说效果，不说机制。** 用户关心「会怎样」，不关心「系统怎么做到」。
6. **只说一遍。** 设计原则第 5 条：标题里有的，副标题和提示不再重复；状态标签已经说明的，说明文字不复述。
7. **推测要标明。** 设计原则第 11 条：模型摘要、估算、推测的原因前写「推测」「约」「估算」，不写成确定的状态。

### 2.2 口语 → 书面

| 不用 | 用 |
|---|---|
| 在跑、跑起来、跑过 | 运行中、开始运行、运行过 |
| 干活、接着干、开工、领活、接活 | 处理、继续、开始处理、接收需求 |
| 派活、派给、交给（指需求时）、交出 | 指派 |
| 没动静、没动 | 无进展、无活动 |
| 在等 | 等待 |
| 卡住了 | 受阻 |
| 做完了 | 已完成 |
| 没人在做、没人接手 | 未指派、无会话处理 |
| 管不到 | 无法控制 |
| 一切正常 | 暂无待处理事项（写具体状态，不写空泛评价） |
| 出了点问题 | 未知错误 |
| 收尾 | 结束 |
| 去看、去处理 | 查看、处理 |

### 2.3 官腔 → 平实

| 不用 | 用 |
|---|---|
| 该会话已结束 | 「x」已结束 / 会话已结束 |
| 请刷新后查看 | 刷新后查看 |
| 主助理代为决定 | 主助理代答 |
| 将显示在此处 | 会显示在这里 |
| 进行压缩 | 压缩 |
| 予以驳回 | 退回 |

「请」只留在操作步骤里需要强调的地方（「请到终端确认」可以写成「到终端确认」时就不写）。

### 2.4 人称

| 场合 | 规则 | 例 |
|---|---|---|
| 要区分动作是谁做的（你 / 会话 / 纸鸢） | 用「你」 | 时间线「你通过了 R-12」；来源「你创建 / Agent 记录」；「你的答复」 |
| 提示、说明、按钮、空状态 | 省略主语 | 「发送后立即继续」，不写「你发出后它立刻接着干」 |
| 要用户做的事 | 祈使句，省略主语 | 「到会话所在的终端确认」 |
| 状态、分区名 | 不带人称 | 「等待授权」「待处理」，不写「等你授权」「要你处理」 |
| 指称会话 | 会话名「x」，或「会话」；**不用「它」** | 「已指派给「x」，待命中，马上开始」 |
| 指称进程、设备、文件 | 写名字或省略；不用「它」 | |
| 指称系统 | 「纸鸢」 | 「纸鸢不修改仓库」 |
| 「您」「我」「我们」 | 不用 | 例外：写给模型的命令文本（如 `compactCmd`） |

**Agent 一词：** 指具体实例一律写「会话」；只有和「你」对举、泛指 AI 一方时保留「Agent」（「你创建 / Agent 记录」）。不用「智能体」。

### 2.5 技术细节写到哪一层

| 层 | 能出现的 | 位置 |
|---|---|---|
| 0 一般界面（默认） | 产品概念：会话、需求、待命、上下文、模型、token 用量 | 按钮、状态、列表、提示 |
| 1 配置与诊断 | 用户能配置、或要据此判断的量：缓存、token、上下文阈值、退出码、端口、CPU / 内存 | 设置页说明、泳道悬停、进程面板 |
| 2 要用户亲手执行的命令 | `ks role dev`、`/compact`、`git revert <sha>` | 只在「照着执行」的步骤里，等宽字体，整段可复制 |

**任何一层都不出现：** 父进程、hook、注入、MCP、会话键、SIGTERM / SIGKILL（写「正常停止 / 强制停止」）、`ks wait`（写「待命」）、daemon（写「后台服务」）、usage 字段名、提示缓存的有效期机制。设备接入指引属于第 2 层，命令和紧挨着它的一句说明里可以出现 `hook`、`MCP`、`systemd`。

## 3. 各类文字的写法

### 3.1 按钮与菜单项

- **动宾结构，2～6 字**（编号插值不计）：「新建需求」「指派」「复制恢复命令」。
- 单字动词只用在对象已明确的地方：「保存」「取消」「删除」。
- 打开弹窗或二次确认的按钮后加「…」：「停止…」；直接执行的不加。
- 不写「去 xx」（「去验收」→「验收」），不写代词（「给它发消息」→「发送消息」）。
- 同一动作全站同一个词（5.6 动作用词）。

### 3.2 标签与标题

- 名词短语，不写句子，不带句号，不带人称。
- 页面 / 面板标题 2～6 字；字段名 2～4 字。
- 分组标题用状态词或名词：「待处理」「运行中」，不写「要你 xx」「在 xx」。

| 改前 | 改后 |
|---|---|
| 要你处理 | 待处理 |
| 会话已经结束，后台进程还在跑 | 残留进程 |
| 你最后说的话 | 最近一条消息 |

### 3.3 状态

- 状态是**有限集合**，只能取第 5 节列出的词，不在组件里另造。集合写在 `docs/copywriting-rules.json` 的 `statusSets`，前后端测试都按它检查。
- 形式：「已 + 动词」（已完成）、「待 + 动词」（待验收、待回复）、「等待 + 名词」（等待授权）、或固定状态名（运行中、待命、受阻）。
- 同一状态在标签、悬停、时间线、筛选、推送里用同一个词。
- 时长跟在状态后：「运行中 12 分钟」「待命 3 小时」。
- 状态说明（hint）写判定条件，不复述状态名。

### 3.4 空状态

- 主句：「暂无 + 对象」或「没有符合条件的 + 对象」，不带句号。
- 需要时加一句副文案，说**怎样才会出现**，带句号。
- 不写空泛评价（「一切正常」），不拟人（「它会出现在这里」）。主句和副文案不重复。

| 改前 | 改后 |
|---|---|
| 一切正常 / 没有要你处理的事 | 暂无待处理事项 |
| 还没有会话。在任意终端里打开 Claude Code 或 Codex，它会出现在这里。 | 暂无会话 / 在任意终端启动 Claude Code 或 Codex 后，会话会显示在这里。 |

### 3.5 说明与提示（hint、悬停、副标题）

- 一句讲效果：开了 / 点了会怎样；必要时第二句讲例外。最多三句。
- 结论在前，条件在后：「不推送，也不进入待处理」。
- 完整句加句号；短语型悬停（「按 / 聚焦搜索」）不加。
- 默认值写在最后：「默认 30 分钟。」

| 改前 | 改后 |
|---|---|
| Claude Code 会话每次 ks wait 最多等这么久。Claude 的提示缓存 1 小时有效，不超过 55 分钟时醒来缓存还在…… | Claude Code 会话单次待命的最长时间。不超过 55 分钟时，恢复后可沿用缓存。默认且最多 55 分钟。 |
| 会话还在，但它已脱离 Agent（父进程变成了系统），Agent 管不到它；可能仍在用 | 会话仍在运行，但进程已脱离会话控制，可能仍在使用。 |

### 3.6 确认与撤销

- 确认框标题是问句，动词 + 对象：「停止进程？」「删除 P-3？」。
- 正文一句讲后果，一句讲能否恢复，不重复标题。
- 确认按钮用和标题相同的动词（「停止」「删除」），不用「确认」「好的」。
- 撤销条沿用「3 秒后通过」句式（R-218），动作词取 `zh.ts` 的 `VERB` 表。**撤销** = 撤销期内取消刚做的操作；**撤回** = 收回已经生效的放行、决策。

### 3.7 通知、时间线与进展条目

固定句式：**主语 + 动词 + 对象（+ ：内容）**。

- 主语四种：**你**、**身份名或会话名**（「主调度」「「x」」）、**纸鸢**（系统动作）、**会话**（没记具体会话时）。来源确实未知时才写「Agent」。
- 时间线句子带「了」：「你通过了 R-12」；短标签用「已 xx」：「已通过」。
- 对象写编号（印记），编号前后留空格；内容用全角冒号引出：「你留言 R-12：……」。
- 推送：标题 = 事件名 + 空格 + 编号（「新决策 D-12」「待验收 R-12」，不用「·」连接）；正文 = 一条时间线句子。事件名取设置页「推送」里的词：新决策、等待授权、待验收、待回复、设备离线。

### 3.8 失败提示

句式（R-236，`web/src/lib/fail.ts`）：**「{动作}未成功：{原因}。未做改动，可重试。」**

- 原因不用拟人主语：「它的状态已经变了」→「状态已变化，刷新后查看」。
- 兜底：「未知错误」。
- 后端返回、前端原样显示的中文说明用同样的用词，写成「无法 xx：原因」或直接写原因。

### 3.9 数量与时间

数量：
- 阿拉伯数字，与汉字之间留一个半角空格：「3 条」「12 分钟」。
- 量词：**需求、决策、消息、记录、证据：条**；**会话、设备、进程、阶段、计划、文件：个**；**待处理事项：项**；**图：张**。不用「件」。
- 计数标签写「名词 + 数字」：「待处理 3」「运行中 2」。
- 进度写「3 / 5」，斜杠两侧留空格。

时间（**全站中文单位**）：
- 相对时间：「刚刚」「30 秒前」「5 分钟前」「3 小时前」「2 天前」。
- 时长：「12 分钟」「2 小时 5 分钟」「3 天 4 小时」。
- 只有泳道刻度、圆环这类放不下 4 个汉字的位置用 `12m` `2h` 缩写，且只用于时长，不用于「x 前」。
- 绝对时间：今天「14:05」，今年「11 月 5 日 14:05」，跨年「2025 年 11 月 5 日」。
- 截止「至 14:05」；时间段「14:05 – 16:30」（en dash，两侧空格）。

### 3.10 编号印记

- 需求 R-、决策 D-、计划 P-，半角连字符，编号与汉字之间留空格：「通过 R-12」。
- 句子里有编号就不再重复标题（R-151，印记会画出标题）。
- 两条以内全写「R-1、R-2」，三条及以上写「R-1 等 3 条」（R-243，`joinCodes`）。
- 编号不加引号；会话名、项目名、用户填的名称用「」。

### 3.11 搜索关键词

`command.tsx` 里 `keywords` 的同义词（「打回」「添加」）是为了让用户用自己的说法搜到，不是展示文案，可以保留旧叫法；**展示的标题**必须用标准词。

## 4. 标点与格式

| 项 | 规则 |
|---|---|
| 分隔符「·」 | 只用于同一行并列的独立元信息（来源 · 时间 · 数量），两侧各一个半角空格（`common.sep`）。**不连接句子的前后两半**，那里用逗号或句号。快捷键提示用空格：「通过 ⌘↵」 |
| 中英文、中文与数字之间 | 一个半角空格；全角标点前后不加空格 |
| 全半角 | 中文语境用全角标点 `，。：；？（）`；编号、命令、路径、英文专名内部用半角 |
| 引号 | 直角引号「」，嵌套用『』；不用 “” 或 "" |
| 省略号 | 单个「…」只用于打开下一步的按钮（「停止…」）和进行中状态（「生成中…」）；列举用「等」，不用「……」 |
| 箭头「→」 | 只用于菜单路径（「设置 → 账户」）和前后变化（「Opus → Sonnet」）；时间段用「–」；「查看全部」的箭头用图标，不写进文案 |
| 斜杠 | 表示「或」并列、进度时两侧加空格：「通过 / 退回」「3 / 5」 |
| 冒号 | 标签接值用全角「：」 |
| 句末 | 按钮、标签、状态、短语型悬停不加句号；完整句（说明、副文案、确认正文、toast 里的完整句）加句号，包括最后一句 |
| 感叹号、问号 | 不用感叹号；问号只用于确认框标题和问题式占位符 |
| 数字单位 | 数字与单位之间留空格：「50 MB」「1.2 秒」；百分号不空格：「80%」 |
| 分号 | 只用于列举里并列的长分句；能拆成两句的拆开 |

## 5. 术语表

格式：**标准叫法** —— 定义；「不用」列是仓库里出现过、要替换掉的说法。

### 5.1 主体与身份

| 标准叫法 | 英文 | 定义 | 不用 |
|---|---|---|---|
| 会话 | Session | 一次 Claude Code / Codex / DSH 对话实例，界面上的基本对象 | 对话、它、Agent（指具体实例时） |
| Agent | Agent | 只在和「你」对举、泛指 AI 一方时用 | 智能体 |
| 身份 | Role | 会话声明的职责：主助理、顾问、评审、主调度、开发（R-190） | 角色 |
| 主助理 / 顾问 / 评审 / 主调度 / 开发 | Aide / Adv / Rev / PM / Dev | 见 `roles.ts`；中英文切换由 `rt` 负责 | 参谋、助理（界面上） |
| 子任务 | Subtask | 主调度 / 主助理派出的一次性后台子代理，不是身份 | 子代理、子 Agent、subagent（界面上） |
| 后台命令 | Background command | 会话在后台运行的 shell 命令 | shell（作展示名时） |
| 纸鸢 | Kitestring | 系统本身，系统动作的主语 | Hub、服务器（一般界面里） |
| 设备 | Device | 装了 ks 并接入的电脑 | 机器、这台 |
| 后台服务 | Background service | 设备上的 ks daemon | daemon |
| 项目 | Project | 仓库对应的项目 | — |

### 5.2 会话状态

会话任一时刻只取下列一个状态（`statusSets.session`）。都来自明确记录（hook 事件、ks 命令、用户操作），符合设计原则第 11 条。

| 标准叫法 | key | 判定 | 不用 |
|---|---|---|---|
| 运行中 | `running` | 本轮还没结束 | 在跑、工作中、忙、在做 |
| 等待授权 | `waiting_approval` | 工具请求执行权限 | 等你授权、请求执行 |
| 等待回答 | `waiting_answer` | 用提问工具（AskUserQuestion）提问 | 等你回答、在问你 |
| 待回复 | `waiting_reply` | 本轮结束，等用户下一条消息 | 等你回复、这一轮停了、本轮结束 |
| 后台运行 | `background` | 本轮结束，但还有后台命令 / 子任务在运行 | 在等后台任务 |
| 待命 | `parked` | 会话挂起等待网页上的答复、验收或留言 | 在线待命、待命中、挂着等待 |
| 空闲 | `idle` | 会话在，但既没在运行也没待命 | 在线（作会话状态时） |
| 已归档 | `done` | 用户手动移到列表底部；会话再有活动时自动取消 | 已完成（和需求撞名）、已收起 |
| 已结束 | `ended` | 会话结束 | 结束了、关掉 |
| 失联 | `lost` | 所在设备超时未上报 | 离线（指会话时）、断开 |

**附加标记**（叠加在状态旁，不是状态；`statusSets.sessionMark`）：

| 标准叫法 | 判定 | 不用 |
|---|---|---|
| 长时间未回复 | 「待回复」超过阈值 | 久未回复、没动 |
| 待命超时 | 开发会话待命超过「开发待命超时」且没有指派的需求（R-229） | 建议收尾 |
| 停下中 | 用户让会话停下后、会话还没下线：已发出停下提醒，等它完成当前一步、写交接（R-291） | 收尾中、停止中 |
| 已下线 | 常驻会话待命累计超过「空等下线时长」（R-272），或用户让会话停下（R-291），写完交接后退出 | 交接下线、空等下线 |
| 已交接 | 身份已由新会话接任，本会话不再承担这个身份 | 已卸任、卸任 |
| 工具待更新 | 会话用的纸鸢工具版本落后 | — |

**常驻身份的在线状态**（`statusSets.presence`，主调度 / 开发 / 主助理）：**待命 / 运行中 / 空闲**。
**团队会话列表**（`ks team sessions`，`statusSets.roster`）：**待命 / 运行中 / 空闲 / 已结束**。
**设备状态**（`statusSets.device`）：**在线 / 离线 / 未连接 / 已移除**。「离线」只用于设备，不用于会话。

## 6. 自动检查

规则写在 **`docs/copywriting-rules.json`**，前后端共用：

- 前端 `web/src/lib/copy.test.ts`（`cd web && npm test` 会跑）遍历 `zh.ts` 的全部文案（函数用占位参数调用，身份名中英文各取一次），以及 `fail.ts` 的提示。
- 后端用 `internal/copyrules` 读同一份 JSON：`internal/hub`、`internal/mcpserver` 的 `copy_test.go` 检查后端生成的状态标签（送达状态、会话可用状态、需求状态、在线状态），`go test ./...` 会跑。
- 只给网页和推送看的后端文字（推送标题与正文、离开报告、通讯页类别、状态标签、会话时间线上的接任）集中在 `internal/hub/copy.go`，`copy_test.go` 用 `copyrules.Check` 逐条检查（规则同前端，按钮长度除外）。新加这类文字写进 `copy.go` 并登记到 `copyTexts`；网页和会话都读的纸鸢提醒、团队消息按 1.3 节写在各自的文件里。

检查项：禁用词（`forbidden`，与第 5 节「不用」列对应）、「它」、「·」连句、引号、省略号、感叹号、中英文与数字间空格、相对时间缩写、按钮长度（`buttons` 里登记的键）、状态集合（`statusSets`）。

**豁免集中在 JSON 的 `allow` 一处**，不在代码里写行内豁免：

```json
{ "key": "settings.devices.g.*", "rules": ["spacing"], "reason": "安装步骤，第 2 层可写命令和技术名" }
```

- `key` 是文案路径，支持末尾 `*`；`except` 列出不豁免的子路径；`rules` 不写表示所有规则；`reason` 必填。
- 状态集合检查不能豁免。
- 一条豁免如果已经拦不到任何问题（键删了、文案改好了），测试会报错，要把它删掉。
- 还没改造的区域先整体豁免（`reason` 写「第 n 批改造」），改造时删掉对应条目、让规则生效。

新加按钮的键要登记到 JSON 的 `buttons`，否则不检查长度。
